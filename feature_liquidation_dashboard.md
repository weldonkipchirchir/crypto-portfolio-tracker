# Liquidation dashboard

Uses the documented OKX public WebSocket `wss://ws.okx.com:8443/ws/v5/public`, channel `liquidation-orders`, `instType: SWAP`. No key, paid subscription, account state, or user credentials are sent. An explicit Observe button opens one connection for up to eight seconds, filters BTC-USDT-SWAP or ETH-USDT-SWAP, and closes after 100 records. Messages larger than 100 KB are ignored; group/detail iteration is bounded. A two-instrument, 60-second browser memory cache bounds repeated connections. There is no retired REST liquidation endpoint, scraping, or invented data. CSP must permit exactly this WebSocket origin.

Official source checked 2026-11-04: https://www.okx.com/docs-v5/en/#public-data-websocket-liquidation-orders-channel . Current docs explicitly warn these records do not represent all OKX liquidations. The feed is public but network/regional restrictions can prevent access; failure and interrupted coverage remain visible. No events before the explicit observation, no historical/backfilled/global totals, and no inference that an empty observation means zero market liquidations. Availability was not live-verified in this restricted network.

`sz` for SWAP is contracts; it is never labeled coin quantity. `bkPx` is liquidation mark price, not a verified fill price. `posSide` long/short identifies the liquidated position; net order sell closes long, buy closes short. Unknown modes stay unknown. Quote is USDT, which is not treated as USD. Contract metadata and FX are not fetched, so USD notionals and totals stay null/Unknown. Aggregate counts cover only displayed reported records; identical records deduplicate using reported fields because no event ID is supplied. UTC exchange event time and UTC observation interval are displayed separately. Late or out-of-order events are possible.

Validation: `node --test feature_liquidation_dashboard.test.cjs`; `python -m unittest test_feature_liquidation_dashboard.py`. Tests use labeled synthetic fixtures, never served to users.
